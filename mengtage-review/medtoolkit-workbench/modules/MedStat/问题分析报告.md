# MedStat 问题分析与解决方案

## 问题1：缺失值仍为0%

### 根本原因分析

**可能原因（按可能性排序）：**

1. **数据集使用占位符** ⚠️ 最可能
   - CSV/Excel中缺失值常用占位符：NA, N/A, null, -999, -9999, ".", 空字符串
   - `pd.read_csv()` 默认只识别特定格式的 NaN
   - **解决方案**：在读取时指定 `na_values` 参数

2. **缺失值是字符串"NA"或"null"**
   - 这些值不被 `df.isnull()` 识别
   - **解决方案**：使用 `df.replace()` 转换后再统计

3. **数据集确实无缺失值**
   - 如果所有数据集都无缺失值，则功能正常
   - **验证方法**：手动检查CSV文件

4. **Excel文件读取问题**
   - Excel中空白单元格可能被某些方式填充
   - **解决方案**：读取后显式替换

### ✅ 已实施的修复

```python
df = pd.read_csv(
    file,
    na_values=['', 'NA', 'N/A', 'n/a', 'na', 'null', 'NULL',
              'None', 'none', 'NaN', 'nan', '.', '-', '-999',
              '-9999', 'missing', 'Missing', 'MISSING']
)
```

## 问题2：异常值预览无响应

### 根本原因分析

**最可能原因**：

前端JavaScript尝试调用数组方法 `.join()`，但数据可能是：
- `undefined` / `null`
- 空数组 `[]`
- 包含NaN的数组

**错误代码位置**：
```javascript
// templates/index.html 第1996行
${stat.zscore_values.join(', ')}
```

如果 `zscore_values` 不是数组（如 `undefined`），会导致JavaScript错误。

### ✅ 已实施的修复

后端添加了 `convert_numpy_types()` 函数，确保所有numpy类型转换为Python原生类型。

## 问题3：JSON序列化错误（NaN/NaN值）

### 根本原因分析

**问题**：`json.dumps()` 无法处理NumPy的 `np.nan` 值

**错误示例**：
```json
{"ks_stat": NaN, "ks_p": NaN}
```

Python的 `json` 模块不认识 `NaN`（只认识JSON的 `null`）。

### ✅ 已实施的修复

创建了 `convert_numpy_types()` 函数：

```python
def convert_numpy_types(obj):
    if isinstance(obj, (np.floating, np.float64, np.float32)):
        if np.isnan(obj) or np.isinf(obj):
            return None  # JSON的null
        return float(obj)
    # ... 其他类型处理
```

并在所有JSON返回处使用：
```python
return jsonify({
    'success': True,
    'corr_results': convert_numpy_types(corr_results),
    'diag_results': convert_numpy_types(diag_results)
})
```

## 问题5：TableOne无法选择自定义分类型变量

### 根本原因分析

**问题**：用户想手动指定某个变量为"分类型"，但选择器只显示自动识别为分类型的变量。

**原因**：`populateTableoneGroupOptions()` 函数只读取自动识别的 `column_types`，不支持手动修改。
