# MedHunter 人工研究映射与 PRISMA 计数验收 · 2026-11-21

已接入人工报告—研究映射、版本审计、单一选定来源链的 PRISMA 计数预览及 JSON/CSV/SVG 导出。完整 Python 检查130项基础/HTTP/单元+58项统计=188项通过；Chromium33项流程通过。本轮新增14项后端测试、2项桌面流程，均使用合成数据，无模型调用。

## 计数依据与范围

PRISMA 官方提供不同检索来源和新建/更新综述的流程图模板，并要求展示筛选阶段的数量与排除原因。本实现参考其计数结构，自绘流程视图，当前只覆盖单一选定检索及筛选版本，不宣称完成整个综述的来源汇总或全部PRISMA报告要求。来源：[PRISMA 2020 flow diagram](https://www.prisma-statement.org/prisma-2020-flow-diagram)，核对日期2026-11-21。

| 对象 | 本次定义和规则 |
|---|---|
| records | 已下载并进入选定去重来源链的检索记录；同时列出检索命中及未下载数量。未取全时明确为局部计数 |
| reports | 题名摘要最终纳入后拟取得的报告；已取得报告进入全文阶段；未取得单列，不计入全文排除 |
| studies | 人类逐篇确认的研究ID集合大小。相同ID合并计数；一篇报告可以关联多个研究。ID限定在当前选定全文批次，不能自动跨批次归并 |
| 完整性 | `selected_lineage_complete`仅表示选定来源链计数与研究映射完成；来源缺失/变化、检索未取全、待裁决/映射或父批次后续修订时标记`partial_or_historical` |

## 行为与可追溯性

- 仅指定人类裁决者可读取/保存研究映射和预览/导出流程；其他批次身份及模型身份不能访问。接口身份来自令牌，拒绝actor注入。
- 映射前须完成全部全文裁决；每篇最终纳入报告都要填写研究ID、关联理由、页号与逐字摘录，并显式人工确认。摘录匹配只核验来源位置，不自动判定是否确属同一研究。
- 保存映射追加审计事件，不覆盖旧版。提交携带全文裁决事件尾和映射事件尾；过期页面不能覆盖新版本。裁决发生修订后，旧映射失效，研究数恢复未知，待重新人工确认。
- 全文批次固定父阶段版本。父批次后来修改时，图表仍沿用子批次绑定的历史父版本并显示提示，避免把新父计数和旧子结果混算。
- 检索→去重/冲突复核→题名摘要快照逐级核对文件哈希；验证原始记录分组覆盖、代表记录和数量守恒。缺少、被改写或无法核验的来源链，前段数量置null而非0。
- 全部题名摘要排除或全部全文未取得时，可直接从完成的题名摘要批次生成计数，不强造空全文批次。已取得全文时必须选择其全文批次。
- 映射未完成、最终裁决未完成、检索未取全有专门提示。全文排除按最新最终决定的原因代码汇总，每篇排除报告归入一个主原因；既有自由文本批次标记legacy_uncoded。
- 导出前核对预览哈希，数据变化须重新预览。每次导出生成不可变命名的本地JSON快照，保存操作者、时间、选定事件哈希、来源文件哈希、研究映射及历史、取得历史与计数。CSV和SVG含报告哈希及快照标识，可与JSON关联。

当前关系：已导入记录−重复记录=题名摘要筛选记录；筛选记录−题名摘要排除=拟取得报告；拟取得报告−未取得报告=全文评估报告；全文评估=已纳入+已排除+待裁决报告。研究数由确认的ID集合计算，不由报告数推算。

## 下一阶段

当前不合并多个数据库、其他检索来源、增量搜索或多个筛选分支；一条来源链最多追溯256个产物版本。图中数据不等于完整系统综述流程，更不是PRISMA合规认证。下一步应建立显式的综述级来源清单、跨检索重复关系和批次版本选择，再做跨批次报告/研究关联；避免简单相加产生重复计数。

Gemini保持空白、模型结果仍为合成导入；手机暂缓、无GitHub推送。权限仅验收本机HTTP，管理员和磁盘访问仍受信任，哈希链无外部锚定。
